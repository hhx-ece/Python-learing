# M03 修改（约 50 分钟）

## 为什么做这个

这是整个项目里**唯一会改坏已有数据**的操作。删除至少是"整条没了"，修改失败可能留下"名字改了、分数没改"的半条脏记录。
这一关只练一件事：**要么全改，要么一点都不改。**

## 接口契约

| 项 | 要求 |
|---|---|
| 菜单 | `5` 进入修改 |
| 流程 | 输入学号 → 显示当前姓名和分数 → 问新名字 → 问新分数 |
| 不改 | 直接回车表示这一项不改 |
| 两项都不改 | 打印 `没有做任何修改` 并返回 |
| 分数非法（非整数 / 越界） | **整次取消**，打印一句提示（含"取消"即可），不重问、不写入 |
| 学号不存在 | 打印 `未找到该学号学生` |

## 最容易写错的地方

先想清楚这个顺序：

```
读学号 → 找到人 → 读新名字 → 读新分数 → 校验 → 写入
```

如果你写成「读新名字 → 立刻写入 → 读新分数 → 校验失败」，用户就会得到一条"名字变了、分数没变"的记录，而且他不知道。
**先把两个输入都拿到、都校验完，再动数据。**

## 动手步骤

1. 写流程，先不做校验：能改就行，跑通。
2. 跑测试，你会发现 `test_03` 挂了——因为非法分数把数据改脏了。
3. 加校验，注意"整次取消"意味着读到非法分数时**不能已经改过名字**。
4. 补「两项都不改」的分支。
5. 全绿之后，手工做一次反向实验：改成 120，然后查看，确认原分数还在。

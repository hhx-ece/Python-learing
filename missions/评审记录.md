### 你做对的（这几处别再改回去）

1. **`get_int` 的 `continue` 结构**：错误分支只打印、不 `return`，只有全部通过才返回值。这是重试循环的标准写法。
2. **把 `get_name` 抽成函数**：名字校验只写一遍，`add` 里只剩一行调用。
3. **`find_student` + `remove(target)`**：你已经把 M04 的核心设计写出来了——先找到对象、再删对象，而且**`delete_student` 里已经不需要 `global students`**。全局变量从 2 处减到 1 处，这是实打实的进步。
4. **`answer.strip().lower() != "y"`**：一个表达式同时处理空格和大小写，`Y` 也能删了。
5. **`get_int(..., 0, 100)`**：范围由调用方给，函数本身不认识"分数"，职责是干净的。

### 必须改（P0）

**1. 菜单 4 / 5 / 6 用 `break` 占位 → 按「查询」直接把程序关了**

证据：喂一个 `4` 进去，程序的全部输出就是那 7 行菜单，然后结束。

```
'1.添加学生成绩\n...\n0.退出\n'      ← 只有菜单，没有任何提示
```

原因：`break` 的语义是「跳出 while 循环」，也就是退出程序；它**不是**「跳过这一项」。
占位应该打印一句「功能开发中」，然后让循环自然继续（不要 `break`、不要 `return`）。

这条比它看起来严重：用户点「查询」，程序无声消失，他会以为数据丢了。

**2. 找不到人时的文案和契约不一致**

你写的是 `未找到该学生`，契约（README 和 M04 任务书里都有）是 `未找到该学号学生`。
所以 M04 的 `test_04` 红了。

这不是"咬文嚼字"：**契约是给别人看的**，测试、文档、以后的 GUI 提示都靠它对齐。改一个字，4/5 变 5/5。

### 应该改（P1）

**3. 查看还是方框，每个学生占 3 行**

契约写的是「每个学生**一行**：`学号 姓名 成绩`」。你现在两个学生输出 8 行：

```
=============
1001  张三  90
=============

=============
1002  李四  80
=============
```

测试**没有报红**，因为 `assert_row` 只在输出里找「1001 张三 90」这一行——它找到了。
这正是我要你记住的一点：

> **测试是底线，不是标准。** 任务书里的「接口契约」整张表才是标准。

20 个学生时，这个格式要翻 10 屏，而任务书要的是「一眼扫完的列表」。去掉 `====`，一行一个就够。

**4. `get_name` 空输入时静默重问**

```
请输入学生的名字:（直接回车）
请输入学生的名字:（再回车）
```

没有一句「名字不能为空」。用户会以为程序卡住了，或者以为自己按错了。
补一句提示，和 `get_int` 保持同一个风格。

### 建议改（P2，不影响过关）

5. **`get_int(..., 1000, 10000)` 把学号范围写死在删除里**。学号规则是业务规则，今天写在删除里，明天「查询」和「修改」各抄一遍，三处就会漂移。要么提取成常量，要么只在"生成学号"的地方管。
6. **`target == None` → `target is None`**。判断"是不是同一个对象"用 `is`，`==` 是值比较；这里虽然结果一样，但习惯要从一开始就对。
7. **`else: break`**：现在只有 `0` 能走到 `else`，所以"碰巧"对。但读代码的人会以为"任何其他值都退出"。写成 `if menu == 0: break`，以后加分支不容易踩空。
8. `get_name(text)` 的参数名叫 `text`，但传进去的是提示语，叫 `prompt` 更准（小事，但命名是给未来的自己留的注释）。

### 但是：删除功能引入了两个 bug

**1. 判断写反了**

```python
target = find_student(student_id)
if target:                     # ← 找到人的时候，这里为 True
    print("未找到该学号学生")    # ← 于是"找到了"反而打印"没找到"
```

更糟的是：没找到时 `target` 是 `None`，代码继续往下执行 `f"...{target['name']}..."`，
直接 `TypeError: 'NoneType' object is not subscriptable` 崩掉。

测试现场（`test_04` 报错）：

```
请输入你要删除的学生学号:TypeError: 'NoneType' object is not subscriptable
```

正确思路是**早返回**：找不到就提示、然后立刻 `return`，后面的代码一律不执行。
"先处理异常情况并退出，主流程就只剩下顺利的那一条"——这个写法叫 early return，后面每一关都会用到。

**2. 取消之后没有 `return`**

```python
if answer.strip().lower() != "y":
    print("已取消")
                       # ← 这里少了一个 return
students.remove(target)  # ← 于是"取消"之后照样删
print("已删除")
```

测试现场（`test_02`）：

```
未找到该学号学生
已取消
已删除
```

用户看到"已取消"，数据却没了。**这类 bug 比崩溃更危险**，因为它看起来一切正常。

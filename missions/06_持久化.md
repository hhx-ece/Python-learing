# M06 持久化（约 80 分钟）

## 为什么做这个

关掉就没的程序，只能叫练习。这一关之后，它才第一次算"软件"。
它也是后面所有功能的地基：没有持久化，GUI 里的"保存"按钮就没有意义。

## 接口契约

| 项 | 要求 |
|---|---|
| 数据文件 | 与脚本**同目录**的 `students.json`（不是当前工作目录） |
| 启动 | 文件存在就加载；不存在就当空库（第一次运行不是错误） |
| 落盘 | 每次增、删、改之后立刻保存 |
| 学号 | 重启后**不重置**，接着上次的号往下发 |
| 编码 | 文件里中文按原样存（`ensure_ascii=False`） |
| 格式 | 合法 JSON，顶层是对象（不是裸列表） |

## 两个必须自己踩的坑

**坑 1：学号的落盘顺序。**
如果先 `save()` 再 `next_id += 1`，文件里存的还是旧号，重启后新学生会拿到**和上一个人一样的学号**。
顺序应该是：取号 → 写入列表 → 计数器加一 → 保存。

**坑 2：先写临时文件，再替换。**
直接 `open(path, "w")` 会先把文件清空。写到一半崩溃，几十条记录全没。
正确做法：写 `students.json.tmp` → 关闭 → `os.replace(tmp, path)`。

## 动手步骤

1. 定义 `DATA_FILE`：用 `Path(__file__).resolve().with_name("students.json")`，**不要**用相对路径。
2. 写 `save()`：收集 `students` 和 `next_id`，`json.dump(..., ensure_ascii=False, indent=2)`。
3. 写 `load()`：文件不存在直接返回；存在就还原 `students` 和 `next_id`。
4. 在 `add / update / delete` 改完数据后调用 `save()`。注意坑 1 的顺序。
5. 启动时调用 `load()`（放在 `if __name__ == "__main__"` 之前或 `main()` 开头都行，但只能调一次）。
6. 跑测试。全绿之后做**进阶实验**（不测，但要做）：
   - 手动把 `students.json` 改成 `{ 坏数据`，启动程序，看它崩不崩；想清楚"崩"和"提示后退出"哪个更专业。
   - 用任务管理器在保存的瞬间杀进程，看文件会不会变成半个 JSON（有原子写就不会）。

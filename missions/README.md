# 闯关任务：把 v1.2 一步步做成 v1.7

这里没有「参考答案」，只有 **任务书 + 验收测试**。代码全部由你写，测试只负责当验收员：
它把你写的程序当黑盒跑（喂输入、收输出），只看**用户看到的行为**，不管你内部怎么组织。

## 为什么这么设计

上一版我直接给了你 v1.3。你现在指出得很对：**看懂别人的重构，练的是"识别"，不是"构造"**。
识别能力让你觉得"我明白了"，构造能力才决定你能不能在空白文件里写出东西。

所以这一版把 v1.2 → v1.3 的大跳，拆成 6 个小关。每关：

- 只引入**一个**新概念
- 有明确的**接口契约**（菜单编号、输出格式、提示语），因为"给谁用、长什么样"本来就是产品决定
- 有**机器验收**，过不了就是没过，不存在"差不多"
- 有**决策日志**，写不出来说明你还没想清楚，只是碰巧跑通了

## 规则（很重要）

1. **不许先看 `../student_score_system1.3.py`**。它是答案卷，做完 M01–M05 再对照，用来找"我哪里没想到"。
2. 每关先跑测试看它怎么失败，再动手。
3. **卡住 20 分钟以上**才翻 `提示.md`，按顺序看，别一次看完。
4. 测试全绿之后，写 3 行决策日志（见每关末尾）。
5. 一关没全绿，不进下一关。半成品堆三关，等于什么都没学。

## 全局接口契约（六关都遵守）

| 项 | 约定 |
|---|---|
| 菜单编号 | 1 添加 / 2 删除 / 3 查看 / 4 查询 / 5 修改 / 6 统计 / **0 退出** |
| 列表格式 | **每个学生一行**，列顺序 `学号 姓名 成绩`，列之间至少一个空格，**不加冒号** |
| 空库提示 | `没有学生成绩可被找到`（沿用 1.2） |
| 学号不存在 | `未找到该学号学生`（沿用 1.2） |
| 数据文件 | 与脚本同目录的 `students.json`（M06 起） |

为什么列表要一行一个？因为 20 个学生时，1.2 的方框要翻 10 屏——**列表页是给人扫的，不是给人读的**。

3. 还不行，把你的代码 + 完整报错贴给我，我做 code review——**不直接给改好的代码**。
